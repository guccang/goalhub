# GoalHub

本地目标执行工作台。每个项目维护自己的上下文和员工团队。项目负责人根据目标与员工职位定义拆解、分配任务；员工通过配置的宿主执行；负责人跟进进度并核对验收证据。所有轮次的输入、输出和事件保存在 SQLite。

## 启动

需要 Node.js 24+、Git、已登录的 Codex CLI，以及同机的 `agent-runtime`。

```powershell
$env:AGENT_RUNTIME_PATH='F:\Documents\game-engine\tools\agent-runtime\index.mjs'
npm start
```

访问 `http://127.0.0.1:3210`。可设置 `PORT`、`GOALHUB_DATA_DIR` 和 `AGENT_RUNTIME_PATH`。默认数据目录为项目下 `data/`。

## 执行规则

项目完成还必须通过交付验证。Web 支持指定本机端口启动、停止和打开预览；桌面与 App 保存经过构建和验证的安装产物，提供下载与 SHA-256。配置、旧项目补建及平台要求见 [项目交付](docs/delivery.md)。

- 每个项目绑定已有 Git 仓库，或在 `data/projects/<id>` 创建独立 Git 仓库，开发 Agent 使用 `data/worktrees/<id>`，评估 Agent 使用一次性的隔离 worktree。
- 规划 JSON 必须包含可执行任务和可验证的验收项。规划判定需要用户资料时会暂停，提交回答后沿用原目标重新规划。
- 执行 Agent 一轮只处理当前任务；评估 Agent 定时检查阻断并提出修复建议。调度器在开发目录中实际运行规划列出的验收命令；全部测试和最终评估通过后才标记完成。
- 输入、最终输出、流事件、会话 ID、任务状态、评估结论均写入 SQLite。页面支持查看步骤历史。
- 服务重启后，将未完成的运行恢复为暂停状态，用户可继续执行；不会默默重复未确认的 CLI 操作。
- 开发时复用同一项目的 Agent 会话；各次评估使用独立会话。源码检查点保留在开发分支；全部验收通过后合并到登记的主分支，并移除开发 worktree。
- 连续三轮无法推进会记录阻断原因，用户处理外部问题后可继续。Agent 单轮默认 30 分钟、测试单项默认 120 秒，可在创建目标时调整。

页面结构、状态机、数据库和并发策略见 [设计方案](docs/design.md)。执行 `npm test` 验证调度、持久化与接口；测试使用模拟宿主，不消耗模型额度。

## 像素办公室

已接入 Munder Difflin 的开源程序化角色与消息动画，在浏览器中显示规划、开发、评估和测试的真实运行状态。点击角色查看输出，可直接暂停、继续、触发评估和发送补充执行要求。点击普通员工查看个人执行记录、分配任务与相关验收；点击负责人查看项目全部记录，并通过迭代选择查看历史。页面不再提供独立的任务视图和设施导航按钮。

来源版本、MIT 许可、状态映射和控制流程见 [办公室接入说明](docs/munder-integration.md)。运行页面不需要下载第三方前端依赖，也不连接外部可视化服务。

该服务仅绑定回环地址，面向本机个人使用。运行 Agent 和验收命令会修改项目文件，请只在可信机器上启动。

## 四步创建流程

从侧栏「宿主配置与测试」开始：保存宿主与模型 → 真实连通性测试 → 输入目标生成拆解预览 → 自动确认或人工确认 → 开始实现。新项目默认人工确认，确认前不启动开发。配置、探测结果、计划与确认记录均持久化；详细接口见 [四步执行流程](docs/setup-flow.md)。

## 完整像素办公室

办公室已换为 Munder Difflin 原始分层地图与完整场景引擎，支持真实角色状态、寻路、屏幕、气泡、任务看板、消息交接，以及原版咖啡和休闲动画。使用「展开」查看完整地图。构建和适配见 [场景说明](office-engine/README.md)。像素素材由 [LimeZu](https://limezu.itch.io/) 创作，使用独立素材许可；代码遵循上游 MIT 许可。

宿主配置已拆为独立的全局设置窗口，所有目标共享配置与测试结果；新建目标直接填写目标。未保存的配置可通过「测试连通性」自动保存并验证，无需先点保存。

## 项目与多次迭代

先「添加项目」绑定仓库，再在项目内「提出需求」。协调者与开发会话按项目续接，目标历史独立保存。页面提供上下文余量、目标用量、项目累计和整体统计。详见 [项目迭代与统计](docs/project-iterations.md)。
## 项目与员工语言

- 新建目标可选择项目默认语言：中文、English、日本語、한국어；旧项目未设置时默认中文。
- 在「像素办公室 → 管理员工」修改项目默认语言，也可为每名员工单独设置「员工母语」。选择「继承项目语言」时随项目设置变化。
- 员工语言用于办公室气泡和 Agent 的说明、总结、提问、进度消息；目标未特别指定时，交付文案和文档使用项目默认语言。工作台界面仍为中文。
- 运行中需先暂停再保存；后续轮次使用新配置。语言变更隔离执行会话，SQLite 保存配置审计和每轮有效语言，历史内容不重新翻译。
- 办公室休息区使用四语台词库；对话双方分别使用自身有效语言。中文字体继续优先使用提供的字体，缺少日文或韩文字形时使用系统字体回退。

## 动态模型目录

全局宿主配置和项目员工配置均可动态选择 Codex 模型，支持手动刷新。目录通过公共 agent-runtime 的 app-server 查询，沿用已保存的本机、设备码或 API 登录方式，不发起推理回合。认证变更后先保存，再刷新目录。目录读取成功不代表连通性测试通过。

第三方或未在目录中的模型仍可手动填写；暂未提供模型目录接口的其他宿主会明确显示提示。查询失败不会覆盖已填写模型。

## 项目团队

在「管理员工」中配置项目独立员工、职位名称与工作说明，并指定一名负责人。姓名随像素人物同步，任务直接分配给实际员工；无需凑齐固定职责。可复制其他项目团队作为草稿，保存后独立维护。项目上下文统一提供架构、需求背景和规范，宿主认证全局复用。详细模型、迁移与调度规则见 [项目团队说明](docs/office-roles.md)。

Codex 全局配置支持模型思考强度（默认、minimal、low、medium、high、xhigh）。连通性测试携带所选强度，新建项目的默认员工继承该值；项目已保存的员工配置优先。强度变更会使之前的连通性测试失效，具体模型是否接受该值以真实测试为准。

## God 一键搭建团队

目标明确后，在「管理员工」中点击「God 一键搭建团队」，或在「提出需求」时勾选先由 God 搭建团队。GoalHub 独立管理者 God 使用自己的宿主、模型和思考强度，结合目标、项目上下文及现有团队生成员工、职位和工作说明，并指定项目负责人。God 不属于项目团队，项目没有员工也可以直接组队。

生成结果先进入可编辑草稿，可调整人物、职位、模型和工作说明，也可恢复生成前草稿。点击「保存项目团队」后生效，再点击继续执行开始规划。生成不会自动启动开发；关闭窗口后继续生成，重新打开可查看进度或载入方案。支持取消、失败重试，服务重启会将未完成生成标记为中断。

在侧栏「God · GoalHub 管理者」配置全局 God，并查看其跨项目管理记录。首次访问时复制全局宿主作为初始值，之后独立保存；宿主默认值和项目负责人变更不会覆盖 God。认证复用全局宿主设置。组队输出可使用现有员工或全局宿主的执行配置，God 自身配置不会自动分配给项目员工。生成期间不能修改 God 配置。
