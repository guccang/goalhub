# 执行时限与配置来源

项目工作统一读取员工 `timeoutMinutes`，单位为分钟，允许 1–240 分钟。项目默认值只在创建员工或兼容缺失字段的旧员工时使用，不能覆盖已经保存的员工时限。

| 执行环节 | 时限来源 | 调整入口 |
| --- | --- | --- |
| 员工规划、协调、开发、评估 | 实际调用员工 | 管理团队 → 员工 → 处理时限 |
| 任务关联的验收命令 | 当前任务的执行员工 | 同上 |
| 最终验收的每条命令 | 项目负责人 | 同上 |
| 交付构建、产物验证、预览启动等待 | 本次交付负责人的配置快照 | 修改负责人后重新准备交付 |
| God 搭建团队 | God 自身 `timeoutMinutes` | God 设置 |
| 全局宿主连通性测试 | 宿主 `probeTimeoutMinutes`，初始值 2 分钟 | 管理全局宿主 → 连通性测试时限 |

每条命令单独计时；如果一条命令内部串行执行多个测试，它们共用该命令的员工时限。停止、非零退出和进程管道异常仍然使验收失败，不因时限变长而忽略错误。

旧项目保存的 `testTimeoutSeconds` 不再参与执行，也不再出现在创建表单中。旧客户端提交该字段不会覆盖员工时限。验收轮次保存执行员工与时限快照，事件记录配置来源；交付记录保存负责人快照并在日志写明时限。已经运行的命令保持启动时配置，修改员工配置作用于下一次执行。旧交付没有快照时从所属目标读取负责人，不借用其他目标的配置。

## 保留的基础设施超时

以下限制保护单次基础操作，不是项目开发、测试或构建的总时限。本次没有把它们替换为员工时限：

| 位置 | 数值 | 作用 |
| --- | --- | --- |
| `lib/git.mjs` | 仓库登记 10 秒、Git 命令 30 秒 | 防止 Git 子进程永久阻塞；大型克隆可能需要单独治理 |
| `lib/host-auth.mjs` | 登录状态查询 15 秒、设备码登录 15 分钟 | 认证查询与用户授权等待 |
| `lib/delivery.mjs` | HTTP 单次探测 1.2 秒、重试间隔 250 毫秒 | 在负责人启动时限内反复探测服务；单次失败不会提前结束总等待 |
| `lib/store.mjs` | SQLite 锁等待 5 秒 | 数据库竞争保护 |
| 公共 `agent-runtime/codex-models.mjs` | 模型目录查询 30 秒 | 查询目录，不是员工任务 |
| 公共 `agent-runtime/process.mjs` | 强制停止升级 5 秒、停止确认 10 秒、退出后管道排空 2 秒 | 已退出或正在停止进程的回收期限 |

调度排队唤醒、失败退避、页面轮询等间隔不属于任务执行超时。DeliveryManager 与 TeamBuilder 的短时限注入仅供自动化测试使用，生产构造不传入覆盖值。
