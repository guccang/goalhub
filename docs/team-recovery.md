# Team recovery

任务连续失败三轮后，如果属于员工明确返回 retry 或真实验收失败，平台最多自动升级主管恢复一次。主管重新核对失败证据、前置依赖及员工能力，安排后续执行；再次耗尽重试时保留 blocked 状态，避免无限消耗。

主管分配协议支持 `prepareDelivery: true`。平台先提交当前源码检查点，再按仓库 `goalhub.delivery.json` 执行独立构建及验证。成功后把交付记录和构建目录交给执行员工，不把开发目录旧安装包当成新产物。失败保留构建日志，不会伪造完成。

协议错误及宿主错误仍在三轮失败后暂停。暂停面板明确说明执行已经停止，提供“交给主管恢复执行”；该操作先清除未完成任务的旧分配，让主管重新接手。已完成分工和当前需求保留，不要求用户填写技术修复方案。
