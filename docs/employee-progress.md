# 员工工作进展

员工详情依次回答目标、正在做什么、计划与剩余任务、已完成成果、上下文来源。团队切换、执行配置及原始宿主日志默认折叠。

- 目标使用来源版本仍有效的需求快照，否则明确展示原始目标；其他目标和历史目标分别读取。
- 计划与剩余任务仅展示员工本轮最新上报的执行步骤，统计来自该计划的完成标记，不代表项目验收结果。未上报时明确说明，不使用主管拆解的项目任务替代个人计划，也不展示项目完整分工。
- 当前工作展示员工最近说明和工具活动时间。员工说明不代表验收通过；已完成成果仅取状态为 done 的任务及其结果。
- 个人计划不混入项目任务的验收详情；前置依赖与交接成果保留在上下文区。
- 上下文区区分当前需求、仓库中的前置成果、本轮实际输入。旧执行记录若没有收到前置结果，会明确标注。后续输入保留直接依赖的描述和完整交接结果，不注入无关历史成果。
- 执行记录接口返回最近 100 条流事件；窗口每次工作台轮询时刷新。主视图提取最近员工说明及工具活动，其他宿主数据保留在诊断区。不识别的事件不猜测为进展。
- 员工说明与工具证据分开；长命令和路径在详情查看。最终结构化回复展示 summary，原始结果与输入仍保存在数据库及提示词入口。

后续规划要求复杂产品按可验证阶段拆分，明确输入路径、交付物和可观察的验收行为；执行员工在阶段变化时报告已做、正在做和剩余事项。规则作用于后续调用，不中断或重写已经发出的任务。

验证：隔离数据库/API 测试覆盖流事件、目标隔离、需求失效、交接保留和 HTML 转义；使用生产数据库的隔离快照检查员工详情、执行窗口、实时刷新与窄屏布局，不启动快照中的员工任务。
