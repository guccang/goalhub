# 项目、迭代与统计

## 使用步骤

1. 点击「添加项目」：登记已有 Git 仓库根目录，或选择新的空目录；不填目录时由 GoalHub 管理仓库。此步骤不调用模型。
2. 配置并测试宿主，在项目内提出需求，选择自动执行或人工确认。
3. 协调者读取代码和历史上下文，必要时提问；生成总体计划、任务依赖、负责人和完成条件。人工确认模式可调整计划后再批准。
4. 开发在项目 worktree 中执行。检查点只提交到开发分支，验收通过后才合并登记的主分支并清理 worktree。主目录有未提交改动或分支不符时暂停合并。
5. 完成后继续提出下一次需求，复用项目仓库以及协调者、开发者会话。下拉菜单可查看历史迭代，其执行按钮禁用。

## 上下文与恢复

- 项目保存目标历史、问答、总体计划、结构化任务、运行记录和提交证据。
- 同项目、宿主、模型及会话代次下续接协调者和开发者；评估者使用独立会话。
- 新一轮提示包含最近 12 次历史迭代摘要，完整历史仍保存在数据库。
- 服务重启恢复为暂停，用户继续执行后恢复会话；宿主会话不可用时可重置项目会话，历史不会删除。
- 长对话压缩由宿主负责；复用会话不意味着无限上下文。页面在宿主上报时显示压缩记录。

## 统计口径

- 上下文窗口、当前占用与剩余比例使用宿主最近一次上报，不能用累计消费推算。未上报显示「未知」。
- Codex 从明确会话的本地记录读取上下文；结束事件的会话累计用量按启动前基线差分，避免多次迭代重复计费。
- 支持 Codex、Claude Code、OpenCode 的对应用量事件；其他宿主及缺少统计的版本保持未知。实际模型名称在宿主上报时更新。
- 输入包含缓存部分，输入与输出相加得到总量；缓存读取不重复相加。耗时是完成运行耗时之和，不等于并行执行的墙钟时长。
- 提供本目标、项目累计、整体累计，以及日期（UTC）、项目、目标、角色、模型明细；上报覆盖率说明有多少轮提供了数据。
- 旧运行不反推 tokens；无统计的记录不会显示成零消耗。模型价格与账单费用未纳入本功能。

## 迁移与验证

启动时自动将旧项目转换为首个目标，关联原有任务、问答、运行和提交；迁移可重复执行。建议升级前备份 SQLite。

`npm test` 使用模拟宿主与真实 Git 验证两次迭代、重启续接、历史隔离、主分支验收门槛和统计差分，不消耗模型额度。真实宿主是否上报数据取决于安装版本和认证状态。
