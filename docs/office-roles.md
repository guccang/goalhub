# 办公室员工与设施

办公室沿用 Munder Difflin 场景和人物，职位、执行宿主、当前工作分别展示。

| 职位 | 人物 | 真实执行记录 |
| --- | --- | --- |
| 项目经理 | Michael | planner：目标澄清、任务拆解、验收标准 |
| 软件工程师 | Jim | developer：开发与修复 |
| 技术主管 | Dwight | evaluator：周期进度检查与技术阻塞 |
| 质量工程师 | Pam | final-review：测试证据及最终交付验收 |

测试工作站属于设施，对应 test 进程，保留真实命令输出及退出码。它不会生成像素员工，也不会把质量工程师标成工作中。质量工程师仅在真实 final-review 轮次运行时工作。原有 SQLite 轮次及角色 ID 无需迁移。

设施栏提供任务看板、会议桌、测试工作站和档案柜：分别连接任务列表、待答问题/计划确认/补充要求、测试轮次记录和完整输入输出。原版场景道具入口继续可用。

## 项目员工管理

点击办公室「管理员工」可新增、删除、改名、启停员工，并配置职责、形象、执行宿主、模型、思考强度、单轮时限和补充工作要求。每个项目最多 15 名员工；四类职责各至少一名启用员工才能开始执行。允许先保存不完整的团队草稿。同职责多人按轮次分配，开发依然串行，避免多人同时修改同一工作目录。

员工配置存储在该项目的 `settings.employees`。旧项目沿用原设置生成默认四人团队；配置不会影响其他项目。API：`GET/POST /api/projects/:id/employees`。保存时要求项目已停止，`team.updated` 记录配置变更。删除员工只影响后续分配，历史轮次与日志继续保留。

新建目标可勾选「先配置项目员工，再开始规划」，项目创建后保持暂停，保存团队后点击「继续执行」开始规划。各宿主使用全局认证凭据，模型名由对应 CLI 校验。当前公共运行模块仅对 Codex 提供思考强度参数，其余宿主在界面和服务端均禁止填写；Codex 的取值是否可用以所选模型为准。

每轮实际使用的员工、宿主、模型和思考强度保存到 `runs.executor`，详细输入输出页面展示该历史快照。开发会话按员工、职责及配置指纹隔离，更换宿主、模型、思考强度或补充要求后不会复用旧会话。状态和日志来自真实记录，散步等场景动画不表示实际工作。
